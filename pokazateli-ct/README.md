# pokazateli-ct/ — показатели цифровой трансформации

Страница рейтинга ЦИО по кварталам: **8 блоков, 35 подпоказателей, 100 баллов**. По
каждому подпоказателю видно порог, факт и цену вопроса в баллах.

```sh
python3 build.py                                  # → index.html
cd .. && python3 -m http.server 8024 --directory . &
#   → http://127.0.0.1:8024/pokazateli-ct/index.html
```

Сервер поднимается **из корня transformation** — как и для дашборда.

## Расчёт живёт не здесь

Методика, факты и правила подсчёта — в `~/Projects/LIFE/rating/`, `build.py` их
импортирует:

| Что | Где |
|---|---|
| блоки, веса, пороги (восстановлены из заголовков выгрузки) | `LIFE/rating/methodology.json` |
| значения по кварталам | `LIFE/rating/facts.json` |
| правила подсчёта баллов | `LIFE/rating/score.py` |
| живые числа из свежей выгрузки Redmine | `LIFE/rating/live.py` |

**Второй источник значений заводить нельзя.** Квартальная динамика считается по одной
истории; свои факты рядом со страницей означали бы, что учёт в LIFE и эта страница
через квартал разойдутся, и непонятно, какой из них верен. Здесь — только подача.

## Что показывает

- **Балл квартала** и рядом три числа: потолок (сколько станет, когда придут
  недостающие данные), Q2 и Q1 по карточкам Redmine.
- **Ждём данных** — показатели, которые не провалены, а просто не измерены. Их баллы
  висят в «потолке», а не считаются потерей: нет данных ≠ ноль.
- **Теряем баллы** — пороги, которые уже не взять в этом квартале.
- **Восемь блоков** с полосой «набрано / в подвешенном состоянии» и таблицей
  подпоказателей: порог · факт · баллы. Дельта к Q2 у неполного блока считается
  **по потолку** и так и подписана — сравнивать неполные данные с закрытым кварталом
  напрямую нельзя.
- Метка **«живое число»** стоит у подпоказателей, которые не вводятся руками, а
  считаются из свежей выгрузки (сейчас это просрочки).

## Дизайн — общий с панелью отчётов

Страница собирается на дизайн-системе панели (`~/Projects/LIFE/otchety/dsh.py`, возврат
Claude Design, круг 1) — той же, что рисует вкладку «Показатели ЦТ» в панели и страницу
статуса роликов. Разметку компонентов править только там.

Светлая «бумажная» схема на системных шрифтах, без внешних запросов. Правило чтения:
форма знака отвечает, откуда значение (факт · срок · пропуск · расчёт), цвет — хорошо
это или плохо. `styles.css` копируется при сборке и здесь не версионируется.
