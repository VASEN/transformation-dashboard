# report_inbox.py / report_reminder.py — справочник

Вынесено из CLAUDE.md 03.09.2026 (path-scoped).

## Сбор еженедельных отчётов через Telegram (`report_inbox.py`)

Отчёты по проектам приходят владельцу в мессенджер блоками. Раньше он собирал
`ОТЧЕТ_ДД.ММ.md` вручную; теперь блоки пересылаются боту `@ZVVChannel_bot`
(`~/Projects/shared/bin/telegram-bot.py`), а тот складывает их через `report_inbox.py`.

**Парсер не писался.** Формат присылаемых блоков совпадает с тем, что уже читает
`process_report.parse_report`: шапка «ЕЖЕНЕДЕЛЬНЫЙ ОТЧЁТ» игнорируется, строка-
разделитель `▬▬▬ 🔵 ПРОЕКТЫ ТРАНСФОРМАЦИИ ▬▬▬` распознаётся как заголовок группы,
блоки разбираются с `👤`, `🔗`, `✅`, `📍`.

### Как это работает

| Шаг | Что происходит |
|-----|----------------|
| Приём | Проект опознаётся **по ссылке** на Redmine (точно); резерв — нечёткое имя через `find_in_data`. При совпадении по имени бот пишет «(по названию «…»)» — чтобы владелец перепроверил |
| Хранение | `report_inbox/current/<issue_id>.md` + `_meta.json`; повторная присылка **заменяет** блок, а не множит. В git не идёт |
| Список ожидания | Активные проекты из `data.json` — обновляется вслед за Redmine сам (на 26.08.2026 их 17). Сдавшими считаются только те, кого **ещё ждём**: проект, закрывшийся за неделю, иначе досрочно давал «сдали все» |
| Сборка | Когда сдали все — `build` идёт сам: собирает `ОТЧЕТ_ДД.ММ.md`, зовёт `process_report.py` с `--prev` (свежайший прошлый отчёт) и отдаёт обе сводки |
| Закрытие недели | После **полной** сборки цикл архивируется в `report_inbox/ГГГГ-ММ-ДД/`. При `--force` (собрали без опоздавших) неделя остаётся открытой — но цикл старше `CYCLE_MAX_DAYS` (6 дней) закрывается сам при следующем приёме, иначе блоки прошлой недели добирали новый цикл до полноты и уезжали в сводку как свежие |
| Сохранность | Присланное пишется дословно в `current/_raw/` **до** разбора: отчёт живёт только в чате, а разбор выбрасывает строки вне секций и не спасает хвост сообщения, разрезанного Telegram по длине. Перед перезаписью блока прежняя версия копируется в `current/_prev/` |
| Предупреждения | Ссылка ведёт на другой проект (имена разошлись) или досылка беднее прежней (пропал раздел) — бот говорит об этом, а не переписывает молча |

Название проекта в собранный отчёт идёт **каноническое из `data.json`**, а не как
прислали: присылают вразнобой (капсом, своей формулировкой), а сводка уходит
руководству.

### Со стороны бота

Команду помнить не нужно — бот узнаёт отчёт сам:

- **строгий признак** — строка с 🔵/🔴 плюс ссылка на Redmine или секция отчёта;
- **достройка** — блок скопирован без строки «🔵 Название» (так копируют из уже
  отправленной сводки): если в тексте ровно одна ссылка на задачу **и** есть секция
  `✅ Выполнено` / `📍 Текущие этапы`, строка достраивается. Проект определяется по
  ссылке, имя всё равно берётся из `data.json`. Без секции текст не трогается —
  иначе обычная задача «посмотри issues/123, там ошибка» уехала бы в отчёты;
- иначе сообщение уходит в handoff-шину и становится брифом на разработку —
  ровно это случилось 26.08 с блоком без 🔵.

**Лейн не перехватывает всё подряд.** «ок» и «отмена» по брифу разбираются раньше
любых лейнов; в открытом режиме сбора перехватывается только текст с приметами
отчёта, остальное идёт обычным путём (личный лейн `/day`, новые задачи). Иначе
одна пересылка отчёта на несколько часов глушила конвейер и запись в `LIFE/inbox`,
а текст при этом нигде не сохранялся. Секция отчёта засчитывается только
**отдельной строкой**: «подрядчик пишет ✅ Выполнено, поправь дашборд» — это задача.

Под ответами — кнопки «Кого ждём», «Собрать», «Закрыть неделю», «Выйти»; слова
«отчёты», «сводка» работают как `/report`; незакрытый сбор виден в общем `/status`.
Лейн закрывается сам через 12 часов.

### Живость бота

Бот работает на ноутбуке владельца: пока крышка закрыта, он спит. **Сообщения при
этом не теряются** — Telegram хранит их сутки и отдаёт при следующем опросе.

- каждый круг опроса пишется отметка `shared/telegram/heartbeat`;
- при старте бот сравнивает её с текущим временем и, если пропадал дольше пяти
  минут, сам докладывает: «🔌 Снова на связи, меня не было 3 ч 15 мин»;
- `/ping` (или «жив?») отвечает, когда был последний опрос.

Отметка ставится **после** ответа Telegram, а не в начале круга: при недоступной
сети процесс жив и крутится, но опроса нет — свежая отметка врала бы.

Напоминание срабатывает в окне **12:00–17:00 МСК** с отметкой об отправке
(`logs/.reminder-sent`), а не ровно в 12:00: если ноутбук спал, launchd догоняет
задание позже, и строгая проверка часа теряла напоминание совсем — тишина при этом
неотличима от «все сдали».
