# Кураторы, высвобождение и блок «Высвобождение %» — справочник

Вынесено из CLAUDE.md 03.09.2026 (path-scoped: extract_data.py, index.html, js/, css/).

## Кураторы и высвобождение

Кураторы направлений (с 15.06.2026 — четыре): `Кренёва А.А. → Родевальд С.Е. → Гуляев В.А. → Кудряшов Е.С.`
`Комитет и РЦТ` = сумма всех групп кураторов
Формула %: `высвобождение шт.ед. / план_20% × 100`

### Формат файла высвобождения и матчинг (с 15.06.2026)
Новый файл высвобождения содержит колонку **`Ответственный`**: итоги по куратору лежат
в строках-заголовках (где `Ответственный` заполнен, а `Проект` пуст), ниже — строки проектов.
Скрипт автоопределяет формат по наличию колонки `Ответственный` (иначе — старый формат с NaN-строками).

Имена кураторов отличаются между источниками, поэтому матчинг идёт **по фамилии** (`curator_key`):
нормализация — первое слово, lowercase, `ё→е`. Написание различается:
- Redmine (owner): `Кренева`, `Кудряшов` (через «о»)
- Штатка / высвобождение: `Кренёва` (через «ё»), `Кудряшев` (через «е» — опечатка)

**Правильное написание — `Кудряшов`** (как в Redmine). В `extract_data.py` опечатки имён
исправляются через `CURATOR_NAME_FIX` / `canon_name` (`Кудряшев → Кудряшов`) до записи в `data.json`,
чтобы карточка куратора и owner-фильтр дашборда совпадали.

### Доли кураторов: один проект — несколько строк

Проект, который ведут несколько кураторов, разнесён в файле высвобождения по строкам-долям
(строка лежит в блоке своего куратора — по строке-заголовку `Ответственный` выше).
Величина по проекту = **сумма долей**: `extract_data.py` аккумулирует строки одного проекта
(`VYSV_SUM_FIELDS` через `sum_opt`), а не берёт последнюю. Ссылка (`url`) — первая непустая.

Пример (15.06.2026): «Цифровой двойник сотрудника (ИИ)» — 3 строки (Кренёва 5760/2329,
Гуляев 1409/0, Кудряшов 919/0) → внутр. 8088 ч, внеш. 2329 ч; «Анализ проектов ГЧП» —
2 строки (Родевальд + Кудряшов) → 1824 ч.

**Контроль сходимости:** сумма `total_units` по всем проектам должна совпадать с
`vysv_units` куратора «Комитет и РЦТ» (32.30 на 15.06.2026). До суммирования долей
расхождение составляло 27.89 против 32.30.

### Матчинг проектов с файлом высвобождения

Названия проектов расходятся между источниками (в Redmine — `Цифровое нормирование 2.0`,
в файле высвобождения — `Цифровое нормирование`), поэтому сопоставление идёт по
нормализованному ключу `project_key()`: lowercase, `ё→е`, отброшен хвост-версия (`2.0`),
только буквы/цифры через один пробел. Хвост вида `223-ФЗ` версией не считается —
такие проекты не схлопываются.

`extract_data.py` печатает в лог диагностики:
- `Σ проекты, разнесённые по долям кураторов` — сколько строк просуммировано;
- `~ сопоставлены по нормализованному имени` — названия в источниках разошлись (стоит выровнять);
- `⚠️ активные проекты без строки в файле высвобождения` — часы останутся пустыми,
  и на дашборде/в Telegram блок «📉 Высвобождение» у такого проекта не появится;
- `⚠️ неоднозначные названия проектов` — если в Redmine появятся сразу «X» и «X 2.0»,
  их ключи совпадут и неясно, какому из них принадлежит строка высвобождения.
  Данные в этом случае **не применяются к обоим** (иначе цифры задвоятся) — нужно
  развести названия в источниках.

> ⚠️ `fact_hours` тоже суммируется по строкам-долям. Сегодня факт заполнен только у
> однострочных проектов, но если в новой выгрузке автор проставит факт как итог по
> проекту в каждой доле, значение удвоится — проверять при смене формата файла.

Соответствие колонок (новый/старый формат, см. `cell_any`):
- шт.ед.: `План, шт. ед.` / `высвобождение, шт. ед.`
- внешнее: `Внешнее высвобождение` / `Внешнее высвобождение, часы`
- внутреннее: `Внутрнее высвобождение` / `Внутреннее высвобождение`

## Блок «Высвобождение %» (вкладка Обзор)

### Layout
Блок находится в правой колонке `.two-col`, внутри `.section-card`, над «Дедлайны по неделям».
Внутренняя сетка — `#vysvGrid` с классом `.vysv-grid` (grid 1fr 1fr, gap 12px).

### Структура рендера
1. **Панель детализации** (`#vysvDetailPanel`, `grid-column:1/-1`) — всегда первой, закреплена сверху.
   Контент обновляется при клике, сам элемент не пересоздаётся.
2. **Карточки кураторов** (compact) — только gauge-полукруг + имя, без данных в теле карточки.
   Всегда все видны, не скрываются и не dim-ятся.
   Активная карточка получает border + box-shadow через класс `.highlighted`.

### Поведение
- По умолчанию: выбран «Комитет и РЦТ», его данные в панели сверху.
- Клик по карточке → highlight переходит на неё, панель обновляется.
- `ownerFilter != 'all'` → highlight и панель переключаются на соответствующего куратора (матчинг по фамилии).

### Ключевые функции JS
- `renderVysvBlock(selectedName)` — главная функция; рендерит структуру один раз, затем только обновляет highlight и панель.
- `_vysvDetailHTML(curator)` — возвращает innerHTML панели: блок «Кадры» (2×3) + блок «Высвобождение» (2 ячейки) + акцентная строка.
- `highlightGauge(ownerFilter)` — обёртка, матчит owner → curator и вызывает `renderVysvBlock`.

### CSS-классы
- `.vysv-grid` — `display:grid`, `1fr 1fr`, `gap 12px`, `padding 16px`
- `.vysv-span2` — `grid-column: 1/-1`
- `.vysv-detail` — панель детализации (фон, border accent, border-radius)
- `.vysv-detail-accent` — акцентная строка «% высвобождения»
- `.highlighted` — highlight активной карточки (border + glow)

## Блок «Высвобождение %» — панель детализации (обновлено 2026-04-03)

### Структура `_vysvDetailHTML(curator)`

**Блок «Кадры»** — сетка 2 колонки, 3 строки:
- Штат (`headcount`) | ККП Штат/Факт (`kkp` / `kkp_fact`) — две строки внутри ячейки
- Итого факт (`fact_total`) | РЦТ Штат/Факт (`rct` / `rct_fact`) — две строки внутри ячейки
- План −20% (`plan_minus20` шт.ед.) | Вакансии (`vacancies`)

**Блок «Высвобождение»** — сетка 2 колонки:
- Внутреннее: `vysv_internal_hours` ч + `(/ 1972).toFixed(1)` шт.ед. (стопкой, часы крупно)
- Внешнее: `vysv_external_hours` ч + `(/ 1972).toFixed(1)` шт.ед. (стопкой)
- `null` → «—»

**Акцентная строка** (`vysv-detail-accent`):
- Слева: `pct_vysv`% крупно; цвет: `=== 100` → `--warn`, `> 100` → `--accent3`, `< 100` → `--danger`
- Справа стопкой: «План `plan_minus20` шт.ед. / Факт `vysv_units` шт.ед.»

**Антипереполнение:** все ячейки имеют `min-width:0; overflow:hidden; word-break:break-word`.

### Новые поля кураторов в `data.json`
- `vysv_internal_hours` — колонка «Внутрнее высвобождение» из НМА-файла (NaN-строки)
- `vysv_external_hours` — колонка «Внешнее высвобождение, часы»
- Для «Комитет и РЦТ» — суммируется по трём группам (`CURATOR_ORDER`)

### Таблица «Проекты — Готовность» (вкладка Обзор)
Цветовая маркировка строк по кварталу дедлайна (`border-left` + `rgba` фон):
- `row-q1` Q1 (янв–март): `#7c6af7` (фиолетовый, `--accent2`)
- `row-q2` Q2 (апр–июнь): `#00e5ff` (циан, `--accent`)
- `row-q3` Q3 (июл–сент): `#00ff9d` (зелёный, `--accent3`)
- `row-q4` Q4 (окт–дек):  `#ffb800` (жёлтый, `--warn`)

Бейджи `Q1: N … Q4: N` в `#qBadgesRow` (section-header), обновляются в каждом вызове `renderProjTable()`.
Приоритет: `row-overdue` / `row-today` объявлены раньше в CSS и перекрывают квартальные классы при совместном применении.
