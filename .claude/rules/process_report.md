# process_report.py — справочник

Вынесено из CLAUDE.md 03.09.2026 (path-scoped).

## Еженедельный отчёт (`process_report.py`)

Скрипт обрабатывает еженедельный `.md`-файл с отчётами по проектам.

### Запуск

```bash
python3 process_report.py ОТЧЕТ_01_04.md
python3 process_report.py ОТЧЕТ_01_04.md --telegram-only   # только файлы Telegram
python3 process_report.py ОТЧЕТ_01_04.md --no-telegram     # только обновить data.json
python3 process_report.py ОТЧЕТ_01_04.md --data data.json  # явный путь к data.json
python3 process_report.py ОТЧЕТ_08_04.md --prev ОТЧЕТ_02_04.md  # diff с предыдущим
```

### Что делает

1. Парсит `.md`-файл (блоки `✅ Выполнено` и `📍 Текущие этапы`)
2. Сопоставляет проекты с `data.json` — по ID из URL `🔗`, резерв: нечёткое совпадение имён (`difflib`, порог 0.6)
3. Пишет `current_status` в найденные проекты
4. Делает резервную копию `data.json.bak`
5. Генерирует **два файла** Telegram-сообщений

### Выходные файлы

| Файл | Содержимое |
|------|-----------|
| `telegram_priority_ДД_ММ_ГГГГ.txt` | Приоритетные проекты (`is_priority=true`) |
| `telegram_transform_ДД_ММ_ГГГГ.txt` | Трансформационные проекты (`is_priority=false`) |

### Формат Telegram-сообщения

- Строка портфеля в шапке: `📈 Портфель: 20 · ✅ реализовано 2 · 🔄 в работе 18` (только текущий год)
- Секция `✅ РЕАЛИЗОВАНО В 2026 (N)` — сразу после шапки, до проектов в работе
- Заголовок группы со счётчиком: `🔴 ПРИОРИТЕТНЫЕ ПРОЕКТЫ (3)`
- Нумерация проектов внутри группы: `1. 🔴 Электронные ДС с ПИК`
- Сортировка по возрастанию дедлайна
- Секция `⚠️ ИНФОРМАЦИЯ НЕ ПРЕДСТАВЛЕНА` (если есть активные проекты без отчёта)
- Без Markdown-символов (`*`, `_`) — текст готов к ручному копированию в Telegram

Формат одного проекта:
```
1. 🔵 Название проекта
👤 Кренёва А.А.
🔗 https://transformation.rm.mosreg.ru/#/issues/12345
📉 Высвобождение:
   Внутреннее: 9920 ч / 5.03 шт.ед.
   Внешнее:    43340 ч / 21.98 шт.ед.

✅ Выполнено:
...

📍 В работе:
...

ℹ️ Дополнительно:
...
─────────────────
```

Логика полей:
- `👤` — `owner_short` из `data.json` (Ответственный из Redmine, совпадает с фильтром дашборда); резерв — `person` из строки `👤` в MD-файле
- `🔗` — URL из строки `🔗` в MD-файле или поле `url` из `data.json`
- `📉 Высвобождение` — строка выводится только если часы > 0; шт.ед. = часы / 1972; блок скрывается целиком если все значения None или 0
- `ℹ️ Дополнительно` — примечание к проекту из MD-отчёта (см. «Примечания к проекту»); при `--prev` получает `🆕`, если текст изменился

### Секция «Реализовано» (закрытые проекты)

Закрытые проекты не попадают в MD-отчёт, поэтому берутся напрямую из `data.json`
(`status ∈ CLOSED_STATUSES`) — иначе результат года не виден в сводке.

- **Только текущий год** (`config.YEAR`): проекты, закрытые в прошлые годы, в сообщение не попадают
- Дата реализации — поле `closed_at` («Закрыта»), резерв — `defense_at` («Дата и время защиты»);
  проект без обеих дат в секцию не попадает
- Сортировка — от свежих к старым; строка проекта: `N. Название — ДД.ММ.ГГГГ · Ответственный` + `🔗` ссылка
- Ссылка: поле `url`, резерв — `{REDMINE_BASE}/{id}`
- Счётчики шапки: «реализовано» = размер секции (за год), «в работе» = активные проекты
  группы из `data.json` (а не число проектов в MD-отчёте — чтобы не «поехало», если кто-то не сдал статус)
- **Проект, закрытый на отчётной неделе**, ещё присутствует в MD-отчёте: его блок исключается
  из списка «в работе» и остаётся только в секции «Реализовано» — иначе он был бы одновременно
  реализованным и в работе, а счётчик группы разошёлся бы с «в работе N». Исключаются **только те**,
  что реально попали в секцию (`in_completed_section` сверяет объекты со списком `collect_completed`):
  закрытый проект прошлого года или без даты закрытия остаётся в списке отчёта, иначе он исчез бы
  из сообщения совсем. Скрипт печатает перенесённые проекты в лог; `current_status` из отчёта
  при этом сохраняется в `data.json` (фильтр действует только на Telegram-сообщения)
- Строка портфеля выводится, только когда есть `data.json` (при `--telegram-only` без него счётчики
  не с чем сверить); при нуле реализованных выводится `✅ реализовано 0`, а секция не рендерится
- Закрытые проекты без `closed_at` и `defense_at` в секцию не попадают — скрипт предупреждает о них в логе

| Функция | Назначение |
|---------|-----------|
| `completed_date(dp)` | Дата реализации: `closed_at` → `defense_at` → None |
| `collect_completed(projects, priority, year=YEAR)` | Закрытые проекты группы за год, свежие первыми |
| `project_url(dp)` | Ссылка на проект: `url` → `{REDMINE_BASE}/{id}` |
| `_portfolio_line(completed, in_work_count)` | Строка `📈 Портфель: …` для шапки |
| `_render_completed(out, projects, year)` | Секция `✅ РЕАЛИЗОВАНО В ГГГГ (N)` |
| `in_completed_section(proj, completed)` | Проект из MD-отчёта, попавший в секцию «Реализовано» (исключается из группы «в работе») |

### Примечания к проекту (`ℹ️ Дополнительно`)

Свободный абзац в конце блока `✅`/`📍` в MD-отчёте — это примечание к проекту
(«необходим перенос сроков…», «проведено ВКС совещание…»), а не очередной этап.
`split_note()` отделяет его от тела блока; в Telegram-сообщении он выводится
отдельным блоком `ℹ️ Дополнительно:` и пишется в `current_status` (виден на дашборде).

Абзац считается примечанием, если он последний в блоке **и**:
- помечен явно: `ℹ️` / `📝` / `💬` / `❗` / `Примечание:` / `Прим.` / `Доп. информация:` /
  `Дополнительно:` / `Справочно:` — **рекомендуемый способ, срабатывает всегда**; или
- это связный текст: нет строк-пунктов (`•`, `-`, `1.`, `Этап…`) и есть строка
  длиной ≥ `NOTE_MIN_FREE_TEXT_LEN` (100 символов) — так короткие подпункты этапов
  не принимаются за примечание

Даты в начале строки (`11.06.2026 с Мингос проведено…`) нумерацией не считаются
(`LIST_ITEM_RE` требует `\d{1,2}[.)]` без цифры следом).

### Признак приоритетности

Поле `is_priority` в `data.json` — извлекается из колонки **«Приоритетный проект»** файла Redmine.
`is_priority = true` если значение `'Да'`.
При ручном редактировании `data.json` поле можно проставить напрямую.

### Сопоставление проектов (URL → ID)

Поддерживаются форматы URL в строке `🔗`:
- `https://transformation.rm.mosreg.ru/#/issues/11498` (стандартный)
- `https://transformation-back.rm.mosreg.ru/issues/11245` (без `#`)
- Если URL содержит `/projects/` (не `/issues/`) — сопоставление по нечёткому имени (`difflib`, порог 0.6)

### Diff-режим (`--prev`)

Флаг `--prev PREV_REPORT` включает сравнение текущего отчёта с предыдущим.

**Что меняется в выводе:**
- Шапка сообщений: `🔄 Сравнение с отчётом от ДД.ММ.ГГГГ`
- Строки «В работе», которых не было в предыдущем «В работе» → префикс `🆕`
- Строки «Выполнено», которых не было ни в «Выполнено» ни в «В работе» предыдущего → `🆕`
- Проект, отсутствующий в предыдущем отчёте → суффикс `🆕 новый проект` в заголовке

**Вспомогательные функции diff:**

| Функция | Назначение |
|---------|-----------|
| `strip_dates(s)` | Удаляет `(дд.мм)` / `(дд.мм.гггг)` перед сравнением |
| `normalize_line(s)` | Убирает `•`, `-`, `1.`, лишние пробелы; lowercase |
| `_text_to_norm_set(text)` | Текст → множество нормализованных строк |
| `compute_new_lines(cur, prev_comp, prev_cur)` | Строки текущего блока, отсутствующие в предыдущем |
| `find_prev_project(proj, prev_index)` | Матчинг по `issue_id`, резерв — нечёткое имя |
| `build_prev_index(prev_groups)` | Строит `{by_id, by_name}` из разобранного предыдущего отчёта |
| `render_block_with_diff(block_text, new_lines_set)` | Вставляет `🆕 ` перед новыми строками |

Без `--prev` поведение идентично прежнему.

### Парсер `📍`-строк

Поддерживаемые форматы заголовка блока «В работе» в MD-файле:
- `📍 Текущие этапы (в работе):`
- `📍 Текущие этапы:`
- `📍 В работе:`

Все три стрипаются — в `current` попадает только тело блока без заголовка.

### Дашборд и current_status

`index.html` читает `d.current_status` для блока «Статус проекта» (вкладка Детализация).
После запуска `process_report.py` данные сразу отображаются на дашборде.
