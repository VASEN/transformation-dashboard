# pipeline-preview — прогон пайплайна на копиях

## Зачем

`extract_data.py`, `process_report.py` и `overdue_report.py` пишут результат **в текущий
каталог**: `data.json` (+ `.bak`), `telegram_*.txt`, `overdue_tasks_*.txt`. Поэтому
проверочный запуск в корне проекта:

- затирает рабочие файлы, которые уже могли уйти в Telegram;
- на недособранном еженедельном отчёте уводит проекты без внесённого статуса
  в секцию «⚠️ ИНФОРМАЦИЯ НЕ ПРЕДСТАВЛЕНА».

`deploy.sh` в корне запускает **владелец**, когда отчёт собран. Всё остальное —
через этот скилл.

## Как запускать

```bash
.claude/skills/pipeline-preview/preview.sh                          # авто: свежий отчёт + предыдущий
.claude/skills/pipeline-preview/preview.sh --stage report           # только process_report.py
.claude/skills/pipeline-preview/preview.sh --stage extract          # только extract_data.py
.claude/skills/pipeline-preview/preview.sh --report ОТЧЕТ_22.07.md --prev ОТЧЕТ_15.07.md
.claude/skills/pipeline-preview/preview.sh --base HEAD~3            # сравнить с другой ревизией
.claude/skills/pipeline-preview/preview.sh --keep                   # оставить песочницу для разбора
```

Входные файлы по умолчанию определяются как в `deploy.sh` — самые свежие по времени
изменения (`ОТЧЕТ_*.md`, `issues*.xlsx`, `ШТАТКА_ДБ*.xlsx`, `*Данные по высвобождению*.xlsx`).

## Что делает

1. Создаёт песочницу (`mktemp -d`) с двумя каталогами: `base` и `work`.
2. В `base` кладёт скрипты из ревизии `--base` (по умолчанию `HEAD`), в `work` — из
   рабочего дерева. Данные (`data.json`, отчёты, xlsx) — одни и те же копии.
3. Гоняет обе версии: `extract_data.py` → `process_report.py --telegram-only`.
4. Печатает:
   - **диагностики пайплайна** — строки `Σ` (доли кураторов), `~` (расхождение имён),
     `⚠️` (нет строки высвобождения / неоднозначные имена), `✅ Реализованы`;
   - **diff `data.json`** — по полям проектов и кураторов, плюс проверку инварианта
     «сумма шт.ед. по проектам == итог "Комитет и РЦТ"» для обеих версий;
   - **diff telegram-сообщений** — построчно, до 60 строк на файл.
5. Удаляет песочницу (`--keep` — оставить).

Корень проекта не изменяется: скрипт только читает из него и никогда туда не пишет.

## Когда применять

- Правишь `extract_data.py` / `process_report.py` / `config.py` — до коммита.
- Нужно показать владельцу, как изменится форма сводки.
- Подозрение на регрессию: `--base <ревизия>` показывает, что именно поехало.

## Ограничения

- Сравнивает результат, а не покрытие: тесты (`python3 -m pytest tests/`) — отдельно.
- `overdue_report.py` не гоняется (его выход не зависит от правок форматирования сводки);
  при необходимости запустить вручную в песочнице с `--keep`.
- Если базовая ревизия не содержит файла (новый скрипт), берётся рабочая копия.
