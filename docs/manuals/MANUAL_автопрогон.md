# Автопрогон выгрузки — памятка

**Версия:** 24.08.2026 · **Относится к:** `watch_pipeline.sh`, агент `com.vz.transformation-pipeline`

---

## Как пользоваться

**Положите выгрузку Redmine в папку проекта.** Всё.

Имя не важно — `issues.xlsx`, `issues (45).xlsx`, как скачалось. Дальше без вас:

1. файл получает имя `issues_ДД.ММ.xlsx` по сегодняшней дате (по Москве);
2. пересчитывается `data.json`, собирается отчёт по просрочкам;
3. `data.json` коммитится и уходит в оба репозитория → дашборд на Amvera обновляется;
4. собирается справка по срокам от сегодня до ближайшей пятницы;
5. **в Telegram приходит сообщение об итоге.**

Занимает около минуты. Бросили новый файл вечером того же дня — цикл пройдёт заново,
вечерняя картина заместит утреннюю.

---

## Что пришло → что это значит → что делать

### ✅ Дашборд обновлён

Всё прошло. В сообщении — файл, цифры портфеля, справка по срокам и строка про пуш.

Ничего делать не нужно. Проверьте только, что цифры похожи на правду: если проектов
или задач вдруг заметно меньше обычного, значит выгрузка пришла неполной.

Внутри бывает две вариации строки про данные:

| Строка | Значение |
|--------|----------|
| `🚀 data.json закоммичен и запушен` | данные изменились и уехали на дашборд |
| `ℹ️ data.json не изменился — коммита и пуша не было` | выгрузка та же, что уже обработана: в Redmine с прошлого раза ничего не поменялось |

---

### ⚠️ Дашборд обновлён с замечанием

Данные пересчитаны и **закоммичены**, но пуш в один из репозиториев не прошёл —
в сообщении сказано, в какой именно.

**Что делать:** дашборд на Amvera обновится только после ручного пуша. Выполните в папке
проекта:

```bash
git push origin main      # или upstream — тот, что назван в сообщении
```

Частая причина — слетевший доступ к `upstream` (VASEN): его выдаёт владелец репозитория
заново, Settings → Collaborators.

---

### ❌ Автопрогон дашборда упал

Пайплайн остановился. В сообщении — на каком шаге, код ошибки и последние строки лога
**этого** прогона.

**Что делать:** прочитайте хвост лога в самом сообщении — там обычно и причина
(не та колонка в выгрузке, занятый git, кончилось место). Устраните и повторите:

```bash
cd ~/Projects/transformation
./watch_pipeline.sh --force
```

Сам по себе прогон **не повторится** — это сделано намеренно, иначе он крутился бы
по кругу, отправляя сообщение об ошибке каждые несколько секунд.

---

### ⏭ Выгрузка пропущена

Файл найден, но автопрогон решил, что он не сегодняшний, и **не тронул** его.
Две причины, обе названы в сообщении:

| Причина | Когда бывает |
|---------|--------------|
| «Файл изменён ДД.ММ ЧЧ:ММ — не сегодня» | скачали вечером, перенесли в папку утром: при переносе дата файла не меняется |
| «В имени файла дата ДД.ММ, а сегодня ДД.ММ» | вернули в корень старый снимок, например из `archive/issues/` |

**Что делать:** если выгрузка действительно актуальная — запустите вручную:

```bash
./watch_pipeline.sh --force
```

Если это старый файл, попавший в папку случайно, — ничего. Уберите его, когда удобно.

---

### ⚠️ Файл не взят в работу

В папке лежит файл на `issues*`, но это **не выгрузка Redmine** — в нём нет обязательных
колонок. Автопрогон его не переименовал и не тронул, **сегодняшний снимок цел**.

Проверка стоит именно ради этого: переименование затирает файл того же дня безвозвратно,
а выгрузки в git не хранятся и восстановить их неоткуда.

**Что делать:** обычно ничего — уберите посторонний файл из корня. Если это всё-таки
выгрузка (например, изменился формат экспорта Redmine), смотрите `logs/auto-pipeline.log`:
там перечислены недостающие колонки.

---

### ⚠️ Выгрузка не проверена

Проверить файл **не удалось** — сломалось окружение: рассинхрон `numpy`/`pandas`,
недоступный файл, нет прав. Это не диагноз файлу: он оставлен как есть и **не помечен
обработанным**.

**Что делать:** как только причина уйдёт, выгрузка подхватится сама при следующем
появлении файла в папке. Не хотите ждать — `./watch_pipeline.sh --force`.

Типичное лечение окружения:

```bash
pip3 install --upgrade numpy pandas openpyxl
```

## Две строки-приписки

Они не отдельные сообщения, а добавляются к обычным:

- **`↻ прошлый прогон был оборван, выгрузка обработана заново`** — предыдущий прогон
  убили на середине (выключение компьютера, сон). Автопрогон это заметил и переделал
  работу. Ничего делать не нужно.
- **`⚠️ Справка по срокам не собралась`** — данные обновились и уехали, а справка нет.
  Соберите отдельно: `python3 upcoming_report.py --to ДД.ММ.ГГГГ`

## Когда Telegram молчит

Правило простое: **тишина не означает, что всё прошло** — по каждому исходу приходит
сообщение. Из этого есть **одно** исключение.

Если каталог `logs/` стал недоступен на запись (нет прав, кончилось место), автопрогон
не может ни писать лог, ни отправить сообщение. В этом случае приходит только
всплывающее уведомление macOS **«Дашборд: автопрогон встал»**. Если вы его увидели —
проверьте место на диске и права на папку `logs/`.

Второй случай тишины — вы вообще не клали файл в папку: автопрогон просыпается от любых
изменений в папке и молча уходит, если новой выгрузки нет. Это норма.

---

## Что автопрогон НЕ делает

**Не собирает еженедельную telegram-сводку по проектам.** Она строится из вашего
`ОТЧЕТ_ДД.ММ.md`, и автопрогон в середине недели собрал бы её по прошлонедельному
отчёту. Сводку по-прежнему делаете вы, когда отчёт готов:

```bash
./deploy.sh issues_ДД.ММ.xlsx ОТЧЕТ_ДД.ММ.md ОТЧЕТ_предыдущий.md
```

## Управление

```bash
# посмотреть, что было
tail -50 logs/auto-pipeline.log

# прогнать вручную (обходит все проверки «не сегодня / уже обработано»)
./watch_pipeline.sh --force

# посмотреть, что было бы сделано, ничего не делая
./watch_pipeline.sh --dry-run

# включён ли автопрогон
./automation/install.sh --status

# выключить на время / включить снова
./automation/install.sh --uninstall
./automation/install.sh
```

## Термины

| Слово в сообщении | Что за ним |
|-------------------|-----------|
| **выгрузка** | файл `issues*.xlsx`, экспорт задач из Redmine |
| **снимок дня** | выгрузка, уже переименованная в `issues_ДД.ММ.xlsx`; по ним же считаются переносы сроков |
| **`data.json`** | пересчитанные данные, из которых рисуется дашборд |
| **справка по срокам** | `СПРАВКА_сроки_*.md` и `.txt` — что уйдёт в просрочку до конца недели |
| **пуш** | отправка в GitHub; из него дашборд разворачивается на Amvera |
| **`--force`** | «знаю, что делаю»: прогнать, несмотря на проверки даты и «уже обработано» |
